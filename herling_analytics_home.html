⚙ Agenda OAuth instellen (Microsoft + Google)
Belangrijk: je hebt geen beheer-rechten nodig in je klanten's tenant. Je registreert één app in een Microsoft / Google account dat jij wel beheert (bijv. een eigen persoonlijk Outlook/Gmail account). Die app is "multi-tenant" — daarna kunnen klanten inloggen met hun werk-emailadres en toegang geven tot hun eigen agenda, net zoals bij de officiële Outlook of Calendar app.

Geen persoonlijk Microsoft-account? Maak er een gratis aan op signup.live.com (kost 1 minuut). Dat account hoeft alleen voor de app-registratie te dienen.
Hoe krijg ik dit?
  1. Log in op portal.azure.com met jouw eigen Microsoft-account (persoonlijk of zakelijk — niet die van een klant)
  2. Ga naar Microsoft Entra ID (voorheen Azure AD) → App registrations → New registration
  3. Naam: bijv. Herling Analytics Agenda
  4. Account types: kies "Accounts in any organizational directory (Any Microsoft Entra ID tenant — Multitenant) and personal Microsoft accounts (e.g. Skype, Xbox)" — dit maakt het mogelijk dat iedere Microsoft-gebruiker (incl. al je klanten) kan inloggen
  5. Redirect URI: type Single-page application (SPA), URL = …
  6. Register, kopieer de Application (client) ID en plak hierboven
  7. Bij API permissions → Add a permission → Microsoft Graph → Delegated permissions → vink aan: Calendars.Read, Calendars.Read.Shared, User.Read
  8. Geen "Grant admin consent" nodig — elke gebruiker geeft individueel toestemming bij het inloggen

Bij sommige strikte tenants (bijv. enterprise klanten met restrictief consent-beleid) kan het zijn dat een IT-admin van die klant éénmalig toestemming moet geven via deze admin-consent link (vervang YOUR_CLIENT_ID). Dit is een eenmalige handeling per klant-tenant.

Hoe krijg ik dit?
  1. Log in op Google Cloud Console met jouw eigen Google account
  2. Maak een nieuw project (gratis) — bijv. Herling Agenda Sync
  3. Bij APIs & Services → Library → zoek Google Calendar API → Enable
  4. OAuth consent screen → User type: External → vul app-naam + support email in. Publishing status mag op "Testing" blijven (geeft je 100 test-users).
  5. Credentials → Create credentials → OAuth client ID → type Web application
  6. Authorized JavaScript origins: …
  7. Create, kopieer het Client ID hierboven
  8. Voeg eventuele klant-emails toe als test users (consent screen → Test users → Add users)
